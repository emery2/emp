01 Project Overview
Build a multi-tenant SaaS platform made of separately chosen services (HR, CRM,
partners, performance, projects, service desk, and later operations), so each client runs only
what it needs on one shared core that follows its own organizational hierarchy.
Organizations today run on disconnected tools, or on large suites that force them to buy and learn
modules they do not use. EMP offers shared people, roles, approvals, and data, with services that can be
switched on or off per client.
Why this structure
Clients choose services, so entry cost is low and expansion is a configuration change.
Every service must work alone, which keeps the product sellable in pieces and each piece testable.
Authority follows the real company hierarchy, from owners to junior staff.

02 Objectives & Success Criteria
Deliver a secure multi-tenant foundation with automated onboarding.
Ship HR and CRM first, because they are the core product.
Make every service independently usable, with optional integrations between them.
Model the full company hierarchy and the two-part leave approval.
CRITERION TARGET
API performance 95% of standard CRUD requests under 200ms
Availability 99.9% monthly uptime; RPO under 1 hour; RTO under 4 hours
Concurrency 5,000 global users; 2,000 per tenant
Tenant onboarding Automated sign-up to active workspace, no manual provisioning

independence

Service rules that apply to every delivery
Works on core plus hard dependencies only; integrations are optional adapters.
Services never import each other's internals; they use shared contracts.
Disabling a service keeps its data; enabling requires its dependencies.
Technical documentation (OpenAPI, data model, deployment runbooks) is delivered with each phase.
